# TFY 0.1.0 Developer Preview Notes

This preview targets truthful AI-agent I/O token savings at explicit boundaries: CLI tool gateway, generic shell adapter, TFY agent wrapper, MCP stdio, proof-gated code I/O, raw recovery, launch reporting, and release evidence gates.

Supported launch routes for the v1 local gate are `generic_shell`, `tfy_agent_adapter`, and `mcp_stdio`. Named hosts such as Codex, Claude Code, Cursor, OpenCode, and Hermes remain below launch support until real host invocation plus route-bound ledger/raw/no-negative/positive-savings evidence is supplied.

Not supported: provider/API prompt proxying, private Codex hook interception, universal terminal interception, editor auto-hooking, and public RTK superiority claims without a reviewed comparator manifest.


## Preview install channel

The preview can be tested from ordinary project directories through the `token-fuck-you` npm installer package while keeping the user-facing command as `tfy`:

```sh
npm install -g token-fuck-you@preview
tfy start --agent --host codex
tfy start --human
```

GitHub Releases remain the canonical binary source. npm downloads the matching release archive and checksum, verifies the checksum, installs the platform binary, and exposes the `tfy` command. TFY uses two public install channels only: stable via plain `token-fuck-you` / npm `latest`, and public-test via `token-fuck-you@preview`. Preview publishes must use the `preview` dist-tag and must not imply GA readiness or named-host launch support. Later stable releases must move only reviewed stable versions to the npm `latest` dist-tag, so plain `token-fuck-you` installs remain the safest/stable path. Exact version installs use npm syntax such as `token-fuck-you@0.1.0-preview.0` or `token-fuck-you@0.1.1`; npm does not use `token-fuck-you/v0.1.1` for package versions. The repository helper `node scripts/npm-publish-plan.js ...` validates the intended channel and prints the exact npm publish command after the GitHub Release exists; it does not publish by itself.
